# アップロード制限の本番ログ確認

確認日：2026年11月5日（Asia/Taipei）

追補：この調査後、ユーザーの指示によりコードの既定値・環境変数例・Blueprintの回数上限を100回／時へ変更しました。以下は変更前の本番ログの記録です。

ユーザー指定のRenderワークスペース「RESTFULL ATELIER」、サービス `restfull` のログを読み取り専用で確認しました。対象サービスは https://restfull-xhex.onrender.com です。

## 確認できた事実

集計範囲は2026年11月5日09:00:00〜10:00:00（台湾時間）、UTCでは01:00:00〜02:00:00です。

| 項目 | 本番ログの集計結果 |
| --- | --- |
| 同一管理アカウントの商品画像アップロードURL発行 | 60回 |
| 発行分の処理後ファイル容量合計 | 22,932,092 bytes（約21.87MiB） |
| 最初の発行 | 09:04:45.944 |
| 60回目の発行 | 09:52:38.422 |
| 直後のHTTP 429 | 09:52:38.428 |
| 同時間帯のPOST HTTP 429 | 33件（09:52:38〜09:55:29） |

`image_presigned ` を含むログを取得し、`product_image_presigned` の各行の `bytes` を合計しました。取得結果は60件で `hasMore=false` でした。これはURL発行の実績であり、画像の保存成功枚数ではありません。

09:52:38前後のログには、`/admin/catalog/product/product-images/presign/` へのPOSTと `Too Many Requests` が対応して記録されています。

## 判断

60回目の発行直後に次の発行が拒否される時系列は、コードの既定値 `ADMIN_IMAGE_UPLOADS_PER_HOUR=60` と一致します。容量合計は既定の `ADMIN_IMAGE_BYTES_PER_HOUR=209715200`（200MiB）より十分小さいため、**今回の事象は回数制限への到達と判断できる強い根拠があります。**

ただし、本番環境変数の実値とDB内のカウンターは直接取得できていません。上記判断は本番ログの実測とコードの既定値の照合によるもので、環境変数やDBカウンターの直接照合済みという意味ではありません。

## 未取得事項と理由

- Render MCPのサービス詳細には環境変数の値が含まれず、今回利用できるツールには環境変数の読取り機能がありません。
- `restfull-db` は外部接続用IP許可リストが空のため、Render MCPの読み取り専用SQL問い合わせが拒否されました。IP許可リストは変更していません。
- Render管理画面のブラウザは未ログインで、既存セッションからの環境変数確認はできませんでした。資格情報の入力や新しいアクセス権の付与は行っていません。
- 添付画像自体には撮影日時がないため、画像とログ時刻の厳密な同一性は確認できませんが、「1枚発行後に後続が拒否」という画面の状況と一致します。

設定、ソースコード、DBデータ、R2ファイルは変更せず、デプロイも行っていません。この追補文書のみ追加しました。
